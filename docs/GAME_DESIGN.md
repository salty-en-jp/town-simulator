# 企画書：『ツナグマチ』（仮題）

> 交通をつなぎ、お金を稼ぎ、街を育てる ― 経営 × 都市発展シミュレーション

---

## 1. コンセプト

**「線を引くと、街が生まれる」**

プレイヤーは小さな地方の交通会社の社長。何もない平野に駅を置き、線路や道路を引き、人とモノを運んで運賃を稼ぐ。
交通が通った場所には人が集まり、家が建ち、店ができ、やがてビルが並ぶ。
稼いだお金で土地を買い、自社で開発し、さらに路線を延ばす ― **「交通 → 発展 → 収益 → 再投資」** の循環を回し続けるゲーム。

### 参考にする遊びの要素（ジャンルとして）

| 要素 | 本作での扱い |
|---|---|
| 交通会社経営（鉄道・バス） | ゲームの中心。路線とダイヤで収益を生む |
| 物流・産業チェーン | 原料→工場→商品→街 の輸送で産業が育つ |
| 都市の自然発展 | プレイヤーは建物を直接置かず、**交通と需要で街が勝手に育つ** |
| 不動産・自社開発 | 駅前の土地を買って自社ビルや住宅地を開発できる |
| 財務（借入・決算） | 年度決算、借入金、税金で「経営している感」を出す |

### 差別化ポイント

1. **街は"育てる"もの** ― 区画指定の手間はなし。交通の便・地価・需要で建物が自律的に成長する。
2. **物流を自分で組み立てる** ― どの資材をどの工場へ運び、その製品をどこへ届けるかをプレイヤーが決める。届け先によって稼ぎも、育つ工場も、育つ街も変わる。
3. **駅前開発が主役級** ― 「線路を引く前に土地を安く買っておく」投資判断が一番気持ちいい瞬間。
4. **短いセッションでも遊べる** ― 1プレイ30分〜の「シナリオ」と、無限に遊べる「フリーモード」。
5. **PCでもスマホでも、ブラウザでそのまま遊べる** ― インストール不要。PCはOpenTTDと同じ操作、スマホはタッチ向けの操作（詳細は [スマホ対応の検討](MOBILE_SUPPORT.md)）。

## 3. コアループ

```
   ┌──────────────────────────────────────────────┐
   │                                              │
   ▼                                              │
[路線・駅を建設] ─→ [人・貨物を運ぶ] ─→ [運賃収入]   │
        │                  │                      │
        │                  ▼                      │
        │           [沿線の利便性UP]               │
        │                  │                      │
        │                  ▼                      │
        │      [人口増・建物成長・地価上昇]          │
        │                  │                      │
        ▼                  ▼                      │
 [先に土地を買う] ─→ [不動産収入・売却益] ─────────┘
```

物流側のループ（4.5参照）：

```
[資源を工場へ運ぶ] ─→ [工場が生産] ─→ [製品をどこへ届けるか選ぶ]
        ▲                                │
        │              ┌─────────────────┼──────────────────┐
        │              ▼                 ▼                  ▼
        │      [別の工場へ（上流へ）]  [街へ（街が育つ）]   [高く買う所へ（稼ぐ）]
        │              │                 │                  │
        └──────────────┴──── [工場が育つ・地価が上がる・資金が増える]
```

- **短期ループ（数分）**：列車を走らせる → 運賃が入る → 列車を増やす
- **中期ループ（1〜数年）**：路線延長 → 新しい町が生まれる → 開発で稼ぐ
- **長期ループ（数十年）**：都市圏の形成、技術進歩による新車両、大型開発

## 4. ゲームシステム

### 4.1 マップ

- タイルベースの2.5D（斜め見下ろし／アイソメトリック）
- 初期マップサイズ：128×128（将来的に256×256）
- 地形：平地・丘・山・川・海・森
- 高低差あり（トンネル・橋の建設コストに影響）
- 初期状態で小さな村が数か所と、資源（森林・農地・鉱山）が点在

### 4.2 交通

| 種類 | 解禁時期 | 特徴 |
|---|---|---|
| バス | 最初から | 安い・早く作れる・輸送量小。道路が必要 |
| 鉄道（旅客） | 最初から | 主力。建設費高いが大量輸送で高収益 |
| 鉄道（貨物） | 最初から | 産業チェーンをつなぐ |
| トラック | 最初から | 短距離貨物 |
| 高速鉄道 | 技術開発後 | 長距離都市間で大きな収益 |
| 地下鉄 | 技術開発後 | 都市部で土地を使わずに輸送 |
| 船 | 中盤 | 港どうしの大量貨物 |

- **線路の敷設**：ドラッグで引く。勾配・カーブ半径で速度制限
- **駅**：規模（小・中・大）で発着本数と集客範囲が変わる
- **信号・分岐**：最初は単純な閉塞のみ（複雑な信号は将来拡張）
- **ダイヤ**：「始発〜終電の運行本数」「停車駅」程度のシンプルな設定。細かい時刻表は作らない

### 4.3 旅客・需要モデル

各建物は「住人」「勤め先」「買い物先」を持ち、人は目的地へ移動しようとする。

- **需要の発生**：住宅 → 職場・商業 への移動需要が毎日発生
- **経路選択**：徒歩・バス・鉄道のうち「所要時間 + 運賃 × 係数」が最小のルートを選ぶ
- **満足度**：混雑・待ち時間・遅延で低下 → 利用者が減る／沿線の発展が鈍る

簡易式（調整用の初期値）：

```
移動コスト = 所要時間(分) + 運賃(円) / 時間価値(円/分)
時間価値   = 地域の平均所得に比例（初期 20円/分）
```

### 4.4 街の成長

プレイヤーは建物を直接置かない（自社開発を除く）。各タイルに **「発展ポテンシャル」** を計算し、閾値を超えると建物が建つ・建て替わる。

```
発展ポテンシャル =
    交通アクセス値   × 0.40   // 駅・バス停からの距離、運行本数
  + 周辺の人口密度   × 0.25
  + 雇用・商業の近さ × 0.20
  + 環境（緑・水辺） × 0.10
  − 公害（工場・騒音）× 0.15
```

建物のランク：

| ランク | 住宅 | 商業 | 業務 |
|---|---|---|---|
| 1 | 一軒家 | 個人商店 | ― |
| 2 | アパート | スーパー | 小さな事務所 |
| 3 | マンション | 商店街 | オフィスビル |
| 4 | タワーマンション | 百貨店 | 高層ビル |
| 5 | ― | 大型複合施設 | 超高層ビル |

- 建物の種類は周辺の用途バランスで自動決定（住宅が多ければ商業が育ちやすい等）
- 衰退もある：交通の便が落ちる・公害が増えると空き家化

### 4.5 物流・産業チェーン（★コアシステム）

> **「どの資材を、どの工場に運び、その製品を、どこへ届けるか」をプレイヤーが決める。**
> 旅客と並ぶ本作のもう一つの柱。運び先の選び方ひとつで、稼ぎも、どの街が育つかも変わる。

#### 4.5.1 産業と貨物の一覧

| 段階 | 産業 | 入力 | 出力 |
|---|---|---|---|
| 一次 | 森林 | ― | 原木 |
| 一次 | 農場 | ― | 穀物・野菜 |
| 一次 | 牧場 | 飼料（任意） | 家畜 |
| 一次 | 鉄鉱山 | ― | 鉄鉱石 |
| 一次 | 炭鉱 | ― | 石炭 |
| 一次 | 採石場 | ― | 石材 |
| 一次 | 油田 | ― | 原油 |
| 二次 | 製材所 | 原木 | 木材 |
| 二次 | 食品工場 | 穀物・野菜／家畜 | 食料品 |
| 二次 | 製鉄所 | 鉄鉱石 **＋** 石炭 | 鋼材 |
| 二次 | セメント工場 | 石材 **＋** 石炭 | セメント |
| 二次 | 製油所 | 原油 | 燃料・化学品 |
| 二次 | 発電所 | 石炭 または 燃料 | 電力（周辺の街・工場に供給） |
| 三次 | 建材工場 | 木材 ＋ 鋼材 ＋ セメント | 建設資材 |
| 三次 | 機械工場 | 鋼材 ＋ 化学品 | 工業製品 |
| 三次 | 日用品工場 | 木材 ＋ 化学品 | 日用品 |

```
原木 ─▶ 製材所 ─▶ 木材 ─┬────────────▶ 日用品工場 ─▶ 日用品 ─▶ 街（商業）
                        └─▶ 建材工場 ─▶ 建設資材 ─▶ 街（ビル建設）
鉄鉱石 ┐                      ▲
石炭  ─┴▶ 製鉄所 ─▶ 鋼材 ──────┤
石材 ┐                         │
石炭 ┴─▶ セメント工場 ─▶ セメント┘
原油 ─▶ 製油所 ─▶ 化学品 ─▶ 機械工場 ─▶ 工業製品 ─▶ 街（業務・オフィス）
穀物・家畜 ─▶ 食品工場 ─▶ 食料品 ─▶ 街（人口増加）
```

- 「入力A **＋** 入力B」の工場は、**両方がそろって初めてフル生産**（比率が崩れると片方が在庫として余る）
- 同じ種類の工場がマップ上に複数ある → **どこに運ぶかを選ぶ余地**が生まれる

#### 4.5.2 プレイヤーが決めること：輸送指令

貨物は勝手には動かない。すべてプレイヤーが「輸送指令」で決める。

**輸送指令 = 「どこで」「何を」「どれだけ積み」「どこで降ろすか」の並び**

```
例：鉄鋼ライン（貨物列車 #12）
  1. 北山鉄鉱山駅   … 鉄鉱石を 満載まで積む
  2. 東炭鉱駅       … 石炭を 50% まで積む（混載）
  3. 臨海製鉄所駅   … 鉄鉱石・石炭を すべて降ろす ／ 鋼材を 満載まで積む
  4. 中央建材工場駅 … 鋼材を すべて降ろす
  → 1に戻る
```

指令で設定できる項目：

| 項目 | 選択肢 |
|---|---|
| 積む貨物 | 貨物の種類を指定（複数指定で混載） |
| 積み方 | 満載まで待つ ／ ある分だけ ／ 指定量（t） ／ 積まない |
| 降ろし方 | すべて降ろす ／ 指定量だけ ／ 降ろさない（通過） |
| 降ろした後 | 工場に売る ／ 倉庫に預ける（4.5.5） |
| 待ち時間上限 | 満載待ちを最大何日で打ち切るか |

- **配分ルール（工場側の出荷設定）**：1つの工場の製品を複数ルートで運ぶとき、「建材工場へ60%、A町へ40%」のように**出荷比率**を決められる
- **優先順位**：入力が足りない工場が複数あるとき、どちらに優先して回すかを設定

#### 4.5.3 「どこへ運ぶか」で何が変わるか

同じ貨物でも、届け先によって結果がまったく違うようにする。

**① 買取価格が届け先ごとに違う**

```
受取額 = 量(t) × 基本単価 × 需要係数 × 距離係数 × 速度係数

需要係数 = 届け先の在庫が少ないほど高い（0.5 〜 1.8）
          ・在庫ゼロ（生産が止まっている工場）→ 1.8
          ・在庫が倉庫上限に近い              → 0.5
距離係数 = 輸送距離に応じて上がる（短距離はほぼ稼げない）
速度係数 = OpenTTD の時間係数と同じ方式：貨物ごとの日数までは満額、超えると段階的に低下
          （生鮮品＝野菜・家畜・食料品ほど日数が短い）
距離     = 積んだ駅から降ろした駅までのマンハッタン距離
```

> 届け先の初期値は OpenTTD と同じ「駅の範囲内で一番近い受け入れ工場」。範囲内に複数あるときだけ、指令で届け先を選べる。

→ 「近くの製鉄所に売るか、遠いけど在庫が切れていて高く買ってくれる製鉄所に運ぶか」という判断が生まれる。
→ 一か所に運びすぎると値崩れするので、**複数の届け先に振り分ける**意味がある。

**② 工場の生産量・規模が変わる**

- 入力が安定して届く工場は **生産量が増え、規模がランクアップ**する（小→中→大）
- 届かなくなった工場は縮小し、最後は閉鎖
- つまり「どの工場を育てるか」をプレイヤーが選べる

**③ どの街が育つかが変わる（不動産との連動）**

| 届ける製品 | 街への効果 |
|---|---|
| 食料品 | 人口の上限が上がる |
| 建設資材 | ランク3以上のビルが建つ（届いた量だけ建設が進む） |
| 日用品 | 商業施設が育つ |
| 工業製品 | オフィス・業務ビルが育つ |
| 電力 | 供給範囲の工場の生産効率UP、街の発展ポテンシャルUP |

→ **自社で土地を買い占めた街に建設資材を集中的に送り込み、地価を一気に上げる**、という戦略が取れる。
物流が「運賃稼ぎ」だけでなく、**街づくりの道具**になるのが本作の肝。

#### 4.5.4 工場の在庫と生産

- 各工場は **入力在庫** と **出力在庫** を持つ（それぞれ上限あり）
- 出力在庫が満杯になると **生産が止まる** → 製品を運び出さないと上流もつまる
- 生産は1日ごとに計算：

```
1日の生産量 = 基本生産量 × 規模 × min(入力A充足率, 入力B充足率, …) × 電力係数
```

- 一次産業は入力なしで生産するが、**運び出された割合（輸送率）**が高いほど生産量が伸びる

#### 4.5.5 倉庫・積み替え拠点

- 駅や港の隣に **倉庫** を建てられる（自社施設）
- 倉庫に貨物を貯めておき、値段が上がったときに出荷できる（相場を読む楽しみ）
- **積み替え**：トラックで集めて倉庫へ → 貨物列車でまとめて長距離輸送 → 港で船へ
  - 山奥の小さな鉱山はトラック、幹線は鉄道、という使い分けが生まれる

#### 4.5.6 自社工場

- 所有地に **自社工場** を建てられる（不動産システムと連動）
- 自社工場は「何を作るか」を選べる（例：建材工場で建設資材を作るか、木材を日用品に回すか）
- 自社工場の製品は **自分で売り先を決めて販売** できる（運賃ではなく販売益が入る）
- 他社（AI）工場との違い：建設費がかかる代わりに、利益と生産方針を自分で握れる

#### 4.5.7 供給契約

- 工場や町から「毎月 鋼材500t を届けてほしい（3年契約）」といった **契約の依頼** が来る
- 達成すると通常より高い単価＋評判アップ、未達だと違約金
- 安定収入を取るか、相場で稼ぐかの選択肢になる

#### 4.5.8 物流を「見える化」するUI

物流は複雑になりがちなので、**今どこで何が詰まっているか**がすぐ分かることを最優先にする。

- **物流フロー図**：工場をノード、輸送ルートを矢印にした図。矢印の太さ＝月間輸送量
- **貨物マップ**：マップ上に貨物の流れを色付きの線で表示（貨物の種類ごとに色分け）
- **工場パネル**：入力・出力の在庫ゲージ、生産率、「石炭が不足しています」などの原因表示
- **相場表**：貨物ごとに、各工場・各街の現在の買取単価を一覧表示 → どこへ運ぶか決める材料
- **アラート**：「臨海製鉄所の出力在庫が満杯（生産停止中）」など

### 4.6 不動産・自社開発

本作の目玉システム。

- **土地購入**：任意のタイルを地価で購入できる
- **地価**：発展ポテンシャルに連動。駅ができると周辺の地価が上がる
- **自社開発**：所有地に建物を建てられる
  - 住宅地（分譲 → 一括売却益）
  - 賃貸マンション（毎月の家賃収入）
  - 商業施設・オフィス（テナント収入、集客で駅利用も増える）
  - レジャー施設（遊園地・ゴルフ場・ホテル：週末需要を生む）
- **売却**：所有地・建物はいつでも売れる（売却益に税）

> 「まだ何もない場所に駅を作る予定 → 先に周辺の土地を買う → 駅開業 → 地価上昇」
> この**先回り投資**の駆け引きを一番の見せ場にする。

### 4.7 経済・財務

| 項目 | 内容 |
|---|---|
| 収入 | 旅客運賃・貨物の受取額・自社工場の販売益・契約報酬・家賃・テナント収入・不動産売却 |
| 支出 | 建設費・車両購入・維持費・人件費・借入利息・税金 |
| 借入 | 資本金と資産に応じた上限まで銀行から借りられる（金利は景気で変動） |
| 決算 | 毎年3月に決算。損益計算書・貸借対照表を表示 |
| 税金 | 利益に法人税、土地に固定資産税 |
| 景気 | 好況／不況のサイクル。不況時は地価が下がる＝買い時 |
| 破産 | 資金がマイナスかつ借入上限に達した状態が一定期間続くとゲームオーバー |

運賃は **距離制**（基本運賃 + km単価）。プレイヤーが運賃水準を調整可能（高くすると客が減る）。

### 4.8 時間とテクノロジー

- 1日＝実時間 約2秒（速度は 一時停止／×1／×2／×4）
- ゲーム内時代：1960年スタート → 年を追うごとに車両・建物が近代化
- 研究ではなく **年代による自動解禁** ＋ 一定条件（売上規模など）による前倒し解禁

### 4.9 自治体・イベント

- 各町に「町長」がいて、要望（例：「駅を作ってほしい」「渋滞をなんとかして」）を出す
  - 達成で補助金・評判アップ
- ランダムイベント：大雨（運休）、観光ブーム、工場誘致、オリンピック開催 など

## 7. 技術構成案

| 項目 | 選定案 | 理由 |
|---|---|---|
| 言語 | TypeScript | 型安全で大規模なシミュレーションコードを保守しやすい |
| 描画 | PixiJS(WebGL) | スマホでも滑らかに描くため、最初からWebGLを使う |
| 入力 | 独自の入力変換レイヤー（Pointer Events） | マウス・キーボード・タッチを「操作の意味」に変換し、PCとスマホで同じロジックを使う |
| 配布 | PWA | スマホのホーム画面に追加すると全画面・オフラインで遊べる |
| ビルド | Vite | 高速な開発サーバー |
| UI | 素の DOM / 軽量フレームワーク（Preact 等） | HUD・パネルはDOMで十分 |
| 状態保存 | IndexedDB（セーブデータ） | ブラウザで完結 |
| テスト | Vitest | シミュレーションロジックの単体テスト |

### アーキテクチャ方針

- **入力・画面・ロジックを分離**：PC用とスマホ用で入力とレイアウトだけ切り替え、ロジックは共通（[スマホ対応の検討](MOBILE_SUPPORT.md) 2章）
- **シミュレーションと描画を分離**：`sim/`（純粋なロジック、決定的）と `render/`（表示）
- **固定ステップの tick**：1 tick = ゲーム内1時間。描画は requestAnimationFrame
- **重い計算は分割**：需要・経路計算は数tickに分散、必要なら Web Worker へ
- **乱数はシード付き**：同じシードで同じ結果 → テストとバグ再現が容易

```
src/
  sim/        # 世界の状態と更新ロジック
    world.ts      // マップ・タイル
    economy.ts    // 財務・決算
    transport/    // 線路・駅・車両・経路探索
    city/         // 発展ポテンシャル・建物成長
    industry/     // 工場・在庫・生産・相場
    logistics/    // 輸送指令・積み降ろし・倉庫・契約
  render/     # 描画
  ui/         # HUD・パネル
  save/       # セーブ/ロード
```

## 10. リスクと対策

| リスク | 対策 |
|---|---|
| シミュレーションが重くなる | 需要計算の間引き・Worker化・空間分割 |
| 序盤が退屈 | チュートリアルで最初の黒字化までを短く。初期村をやや大きめに |
| 終盤に資金があふれて目的がなくなる | 大型開発・高速鉄道・シナリオ目標・ランキングで長期目標を用意 |
| 複雑すぎて分かりにくい | 信号・ダイヤは簡略化。ヒートマップで「なぜ発展しないか」を見える化 |
| 物流の設定が面倒になる | 輸送指令にテンプレート（「往復で満載積み・全部降ろす」）を用意。相場表と不足アラートで次にやることが分かるようにする |
| 届け先が実質1つに決まってしまう | 需要係数で一か所集中を値崩れさせる。同種の工場をマップに複数配置する |
| 既存作品に似すぎる | 名称・アート・UIはすべてオリジナル。「育つ街＋先回り投資」を独自の軸にする |

### 12.1 3層マップ（地域・町・遠く）【2026年11月8日・一旦見送り】

**案**（オーナーより）
- 今の地図を「地域マップ」として、町の範囲（町域）は固定する
- 町を選んで「拡大」すると、その町だけの画面になり、町はその中で無制限に育つ。そこでバス・路面電車など小さめの交通を扱う
- 地域マップから「縮小」すると、飛行機・ヘリ・船などの遠くへの輸送を扱う

**ねらい**
- 町が無制限に広がって土地を埋めてしまう問題をなくす
- 乗り物の役割が縮尺ではっきり分かれる（町の中＝バス／地域＝鉄道・トラック／遠く＝飛行機・船）

**見送った理由**
- プレイしている家族から「セーブが消えるかもしれない今の段階では、何度でもやり直しやすい今のゲームバランスがよい」と意見をもらった
- 遊ぶ側の手間が増える（町の数だけ町の画面が増える）。作る側も、ゲームを3つ作るのに近い
- 代わりに、**火事などのイベントで町が時々減る**形で、町の広がりにメリハリをつける（12.2 の検討とあわせて v0.5.1 で対応）

**もし再検討するなら**（その時のための段取り）
1. 町域を固定し、町域が埋まったら外ではなく上（アパート・高層ビル）に育つ。町域は人口の節目やお金で広げる
2. 町の画面（入らなくても自動でそこそこ回る）でバス・路面電車
3. 今の地図に空港・港を置き、地図の外の「遠くの都市」とやりとり。全国地図はさらに後

### 12.2 イベントの候補（v0.5.1 で火事から入れた）

方針：**プレイヤーの持ち物（線路・駅・列車・お金）には直接の損害を出さない**。町や産業に変化を起こして、遊びにメリハリをつける。

- [x] 火事：町の家が数軒焼ける（v0.5.1）
- [ ] 観光ブーム：しばらく旅客が増える
- [ ] 豊作・不作：農場の生産量が一時的に変わる
- [ ] 鉱脈の発見：鉱山の生産量が増える
- [ ] 大雪・大雨：数日だけ列車が遅くなる（止めはしない）
