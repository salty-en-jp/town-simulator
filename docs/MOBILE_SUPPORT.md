# スマホ対応の検討

> 要望：PCだけでなく、スマホでも遊べるブラウザゲームにしたい。
> 結論：**できる。ただし「最初からそのつもりで作る」ことが条件。** 後から対応しようとすると大幅な作り直しになる。

---

## 1. 結論と前提

| 項目 | 判断 |
|---|---|
| 技術的に可能か | **可能**。本作はもともと TypeScript + Canvas/WebGL のブラウザゲーム想定なので、スマホのブラウザでもそのまま動く |
| 一番の難所 | **操作**。OpenTTD式の操作（右ドラッグ・Ctrl/Shift・キーボード・小窓）はスマホに存在しない |
| 次の難所 | **画面の狭さ**と**処理の重さ**（スマホは発熱・電池・メモリの制約がある） |
| 追加の手間 | UI まわりの作業が **おおよそ1.3〜1.5倍**。シミュレーション部分は共通なので増えない |
| 方針 | **PCが主役、スマホも正式対応**。同じゲーム・同じセーブデータで、操作と画面だけ切り替える |

参考：OpenTTD 本家にもブラウザ版のビルドはある（ソースの `os/emscripten`）が、**タッチ操作向けの工夫はない**。
設定の説明にも「マウス位置固定のスクロールはタッチ画面などでは動かない」と書かれているだけ。
→ 「OpenTTDの操作感のままスマホでも遊べる」は、それ自体が本作の売りになる。

---

## 2. 操作：PCとスマホの対応表

### 2.1 考え方

ゲーム内部では「マウスのどのボタンか」ではなく、**「スクロールする」「建設する」「撤去する」「見積もる」といった"操作の意味"** で処理する。
PCではマウス・キーボードを、スマホではタッチを、それぞれこの"意味"に変換する層を挟む。

```
 PC:   右ドラッグ / Ctrl+ドラッグ / Shift / キー
                       │
 スマホ: 1本指 / 2本指 / 長押し / 切替ボタン
                       ▼
            ［入力変換レイヤー］
                       ▼
   操作の意味：スクロール・ズーム・建設・撤去・見積もり・結合・情報表示…
                       ▼
               ゲームのロジック（共通）
```

### 2.2 対応表

| 操作の意味 | PC（OpenTTD式） | スマホ |
|---|---|---|
| スクロール | 右ドラッグ | **ツール未選択時：1本指ドラッグ**／ツール選択中：**2本指ドラッグ** |
| ズーム | ホイール、`+` `-` | **ピンチ** |
| 建設 | ツール選択 → 左クリック／ドラッグ | ツール選択 → **1本指ドラッグ → 確定ボタン ✓** |
| 撤去（Ctrl） | Ctrl＋ドラッグ | ツール横の **［撤去］切替ボタン** |
| 見積もりのみ（Shift） | Shift＋クリック | 確定前のプレビューで**常に費用を表示**（＝Shiftが不要になる） |
| 離れた駅と結合（Ctrl） | Ctrl＋駅ツール | 駅を置くときに「結合先を選ぶ」ボタン |
| 満載待ちの指令（Ctrl） | Ctrl＋行き先クリック | 指令追加後のメニューで選ぶ |
| 情報を見る | 左クリック | タップ |
| ツールチップ | ホバー／右クリック | **長押し** |
| ツール解除（Esc） | `Esc` | ✕ボタン、または何もない所をタップ |
| 取り消し | （OpenTTDにはない） | **元に戻すボタン**（スマホは誤タップが多いので必須。PCにも付ける） |
| ショートカットキー | `1`〜`9`・`A`・`S`・`F1`〜… | ツールバーのボタン（キーがなくても全機能に届くようにする） |

### 2.3 スマホで一番大事な工夫：「プレビュー → 確定」

指は大きく、どこを触ったかが自分の指で隠れて見えない。そこで建設は**2段階**にする。

1. ドラッグすると、**半透明の線路と費用が表示される**（まだ建たない）
2. 端の **◀ ▶ ハンドル**で長さや位置を微調整できる
3. **✓ ボタン**で確定、**✕** で取り消し

- 指の真上ではなく**少し上に十字カーソルを出す**（指で隠れないように）
- 線路はマスに**吸着**させ、細かい位置合わせを不要にする
- PCでは従来通り、離した瞬間に建つ（設定で「PCでも確認する」も選べる）

## 3. 画面：PCとスマホのレイアウト

### 3.1 PC（OpenTTD式、変更なし）

上部ツールバー、下部ステータスバー、情報は**小さなウィンドウ**（ドラッグ移動・ピン固定）。

### 3.2 スマホ（横持ち推奨）

```
┌────────────────────────────────────────────────┐
│ ¥1,250万  1965/4/12  ⏸▶ │                 │ ☰ │  ← 上：最小限の情報
│                                            ┌─┐│
│                                            │🛤││  ← 右：ツール（縦並び、
│                  マップ                     │🚉││     親指で届く位置）
│                                            │🚆││
│                                            │⛰││
│  ↶元に戻す                    [撤去] [✓][✕] └─┘│  ← 建設中だけ確定ボタン
└────────────────────────────────────────────────┘
```

- **小窓は使わない**。情報は画面下から出る**引き出し式パネル**（半分の高さ ↔ 全画面に切り替え）
- ボタンは指で押しやすい大きさ（**最低44px角**）
- 縦持ちでも遊べるが、メインは横持ち（マップが広く見えるため）
- タブレットはPCに近い画面（小窓あり）＋タッチ操作

### 3.3 画面の切り替え方

- 画面の幅とタッチ有無で**自動判定**（スマホ／タブレット／PC）
- 設定で手動切り替えもできる（タッチ付きノートPCなど）

## 4. 処理の重さ・電池への対策

| 課題 | 対策 |
|---|---|
| スマホは計算が遅い | シミュレーションを **Web Worker（裏側の処理）** で動かし、画面が固まらないようにする |
| 描画が重い | WebGL（PixiJS）で描画。画面に映っている範囲だけ描く。縮小時は建物を簡略表示 |
| 発熱・電池 | 画面が止まっているときは描画を減らす。**アプリを裏に回したら自動で一時停止** |
| メモリ | スマホの初期マップは 128×128。大きいマップは「端末によっては重い」と表示 |
| 目標 | 数年前のミドルクラスのスマホで **30fps以上**、PCで60fps |

シミュレーションと描画は最初から分ける設計（企画書 7章）なので、この対策はそのまま取れる。

## 5. 保存とPC⇔スマホの行き来

- セーブは端末のブラウザ内（IndexedDB）に保存
- **セーブデータをファイルとして書き出し／読み込み**できるようにする → PCで作った街をスマホで続けられる
- 将来の拡張：クラウド保存（アカウント不要の「引き継ぎコード」方式など）

## 6. スマホのブラウザ特有の注意点

| 項目 | 内容と対策 |
|---|---|
| ホーム画面に追加（PWA） | アイコンからアプリのように起動・全画面表示・オフラインで遊べる。**スマホでは「ホーム画面に追加」を推奨**として案内する |
| iPhone の全画面 | iPhoneのSafariはゲーム画面を全画面にできない → ホーム画面に追加すれば全画面になる |
| 画面の向き | ホーム画面に追加したものは横向きに固定できる（Androidは確実、iPhoneは制限あり）。縦持ちのときは「横にすると広く見えます」と表示 |
| ブラウザの標準動作 | ピンチで**ページ全体が拡大**される、長押しで**メニューが出る**、引っ張ると**再読み込み**される → すべて無効化する |
| 音 | スマホは最初にタップするまで音が出ない → タイトル画面のタップで音を有効化 |
| 画面の高さ | アドレスバーの出入りで高さが変わる → それに追従するレイアウトにする |
| 切り欠き（ノッチ） | 画面の角や切り欠きにボタンが隠れないよう余白を取る |

## 7. 開発の進め方への影響

| フェーズ | スマホ関連でやること |
|---|---|
| フェーズ0（試作） | **入力変換レイヤーを最初から作る**。1本指スクロール・ピンチズーム・プレビュー→確定を試作に入れ、**実機のスマホで触って確かめる** |
| フェーズ1（MVP） | 引き出し式パネル、ツールの縦並び、元に戻す、PWA化、自動一時停止 |
| フェーズ2（拡張） | タブレット用レイアウト、セーブの書き出し／読み込み、重さの調整 |
| フェーズ3（仕上げ） | 機種ごとの確認（iPhone / Android、画面サイズ違い）、電池・発熱の調整 |

確認方法：開発中はPCのブラウザでスマホ画面を再現して自動テストし、節目ごとにご家族の実機（iPhone / Android）で触ってもらう。

## 8. リスク

| リスク | 対策 |
|---|---|
| 細かい線路の配置がスマホでは辛い | 吸着・プレビュー・ハンドル調整・元に戻す。複雑な配線（信号の多い駅）は「テンプレートを置く」機能も検討 |
| 物流の指令・相場表など情報量の多い画面がスマホで見づらい | スマホ用は1画面1目的に分割。表は横スクロールではなくカード形式に |
| PCとスマホで操作がズレて混乱する | 「操作の意味」は共通。PCの人がスマホに移っても、ボタンの絵と名前は同じにする |
| 古いスマホで重い | 画質設定（低・中・高）と、マップサイズの上限で対応 |
