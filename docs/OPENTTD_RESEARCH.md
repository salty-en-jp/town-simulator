### 1.2 修飾キー（Ctrl / Shift）― OpenTTD 操作の要

OpenTTD は**ほぼ全ての建設ツールで、修飾キーの意味が統一されている**。これが手に馴染む理由。

| 修飾キー | 意味 | 例 |
|---|---|---|
| **Shift** + 建設 | **費用の見積もりだけ表示**（実際には建てない） | 線路・駅・橋・トンネル・整地すべて |
| **Ctrl** + 線路/道路ツール | **撤去モード**で動く | 線路をCtrl+ドラッグで撤去 |
| **Ctrl** + 駅ツール | 離れた既存駅に**結合する駅を選ぶ** | 駅・バス停・トラック停留所・ウェイポイント |
| **Ctrl** + ドラッグ（範囲系） | **斜め方向に範囲選択** | 解体・植林・運河・整地 |
| **Ctrl** + クローン | 車両を複製し、**指令を共有する** | 車庫のクローンボタン |
| **Ctrl** + 「車庫へ送る」 | 点検だけして戻る | 車両ウィンドウ |
| **Ctrl** + 指令の「行き先」 | 駅をクリック → 「満載待ち」付きの指令になる | 指令ウィンドウ |
| **Ctrl** + 車両一覧/指令表 | 関連する画面（時刻表・グループ等）を開く | 各ウィンドウ |

根拠：`lang/english.txt` の各 `*_TOOLTIP`（例：`STR_RAIL_TOOLBAR_TOOLTIP_BUILD_RAILROAD_TRACK` = 「線路を建設。Ctrl+クリックで撤去。Shiftで費用見積もりのみ」）

### 1.6 ウィンドウの作法

- ほぼ全ての情報が**小さなウィンドウ**として開く。ドラッグで移動、×で閉じる
- **ピン（固定）ボタン**：固定したウィンドウは「全部閉じる」でも残る
- ウィンドウのサイズを既定に戻すボタン（Ctrl+クリックで今のサイズを既定として保存）
- 駅・車両・町・産業は**マップ上のものをクリックするとその情報ウィンドウが開く**
- 車両ウィンドウ：「中央に表示（ダブルクリックで追従）」「車庫へ送る」「指令」「詳細」「改造（リフィット）」「発車／停止」

### 1.7 車両を走らせるまでの流れ（基本操作）

1. 線路を引く → 駅を2つ置く → 車庫を置く
2. 車庫をクリック → 「新しい車両を購入」→ 機関車と貨車／客車を買う（必要なら積む貨物を**改造（リフィット）**）
3. 車両の「指令」ボタン → 「行き先」→ **マップ上の駅をクリック**して指令を追加（Ctrl+クリックで満載待ち）
4. 車両の状態バーをクリックして**発車**
5. 増発は車庫の**クローン**（Ctrl+クローンで指令を共有）

## 第2部 ゲームの仕組み

### 2.1 指令（オーダー）システム

列車ごとに「どこへ行って何をするか」を並べたリストを持つ（`lang/english.txt` `STR_ORDER_*`）。

| 指令の種類 | 選択肢 |
|---|---|
| 停車 | 普通停車 ／ **ノンストップ**（途中駅に止まらない）／ **経由**（止まらずに通過） |
| 積み込み | ある分だけ積む ／ **いずれかの貨物が満載まで待つ** ／ **全ての貨物が満載まで待つ** ／ 積まない |
| 荷降ろし | 受け入れ先があれば降ろす ／ 受け入れ先がなくても降ろす ／ **積み替え（転送）** ／ 降ろさない |
| 改造 | 指令の中で積む貨物を変える（駅で改造も可） |
| 車庫 | 常に行く ／ 必要なら点検 ／ 停止 ／ **間隔調整（団子運転の解消）** |
| 条件分岐 | 車両の状態（積載率・信頼性・年数など）で次の指令へジャンプ |

- **指令の共有**：複数の車両で同じ指令リストを使える（1か所直せば全部変わる）
- **スキップ**：今の指令を飛ばして次へ
- **時刻表**：指令ごとに所要時間・停車時間を設定、自動記入もできる

### 2.2 貨物の運賃（収入の計算式）

`economy.cpp` `GetTransportedGoodsIncome()` より。

```
収入 = 量 × 距離 × 時間係数 × 貨物ごとの単価

距離     = 積んだ駅から降ろした駅までの マンハッタン距離（縦＋横のマス数）
時間係数 = 輸送にかかった日数で決まる（最大255、最小31、その後さらに緩やかに減る）
  ・日数 ≦ days1               → 255（満額）
  ・days1 を超えた分           → 1日ごとに −1
  ・さらに days2 を超えた分     → 1日ごとに −2
  ・31 まで下がった後           → 1/(x+1) 型でゆっくり 1 に近づく
days1 / days2 = 貨物ごとに違う（生鮮品ほど短い）
```

- 貨物の単価は**インフレで上がる**が、**届け先の需要では変わらない**（どの工場に届けても同じ単価）
- **積み替え**のときは途中の車両に「仮の収入（フィーダー分）」が計上され、最終的に届けた車両の収入から差し引かれる

### 2.3 貨物の届け先

`economy.cpp` `DeliverGoodsToIndustry()` より：

- 降ろした貨物は、**駅の集客範囲の中で、その貨物を受け入れる産業のうち駅の看板に一番近いもの**に自動で届く
- つまりOpenTTDでは「どの工場に届けるか」は**駅をどこに置くか**で決まる。複数の工場が範囲内にあっても選べない

**貨物の行き先の決まり方（貨物分配）**：初期設定は「手動」（貨物は行き先を持たず、来た車両に積まれる）。設定で「対称／非対称」にすると、つながっている駅の間で行き先付きの需要が自動計算される（cargodist）。

### 2.4 駅の評価（レーティング）

`station_cmd.cpp` `UpdateStationRating()` より。評価が低いと**産業・町が駅に渡す貨物が減り、待っている貨物も消える**。

| 要素 | 評価への影響 |
|---|---|
| 最後に積み込みに来てからの日数 | 短いほど大幅プラス（最大 +130） |
| 駅で待っている貨物の量 | 少ないほどプラス（最大 +130） |
| 最後に来た車両の速さ | 速いほどプラス |
| 最後に来た車両の年数 | 新しいほどプラス（最大 +33） |
| 町に自社の銅像がある | +26 |

- 評価は一気に変わらず、少しずつ（1回に最大±2）動く
- 船は待ち日数を1/4に数える（船は来るのが遅くて当然、という配慮）

**集客範囲**（`station_type.h`）：バス・トラック停留所 3マス／駅 4マス／港 5マス／空港は最大10マス（「範囲を駅の種類で変える」設定がオフなら全部4マス）

### 2.5 産業の生産量の変化

`industry_cmd.cpp` `ChangeIndustryProduction()` より（標準の「スムーズ経済」の場合）：

- 毎月、各産業は約1/22の確率で生産量が変わる
- 上がるか下がるかは**先月の輸送率（作った量のうち運び出された割合）**で決まる

| 先月の輸送率 | 増える確率 |
|---|---|
| 60% 以下 | 1/3 |
| 60〜80% | 2/3 |
| 80% 超 | 5/6 |

- 生産量が最低まで落ちると閉鎖
- **二次産業（工場）**：届いた材料の量に応じて製品を作る（材料ごとに決まった比率で変換）。**在庫の上限や値段の変動はない**

### 2.6 町の成長

`town_cmd.cpp` `UpdateTownGrowth()` ほかより：

- **最近20日以内に使われた駅**が町の周りにいくつあるかで成長速度が決まる（0〜5駅以上で段階的に速くなる）
- 駅が1つもない町はほとんど成長しない
- 雪国（雪線より上）・砂漠の町は、人口が一定以上になると**食料・水などを届けないと成長しない**
- **地方自治体へのアクション**（町ウィンドウから実行、お金がかかる）：
  - 広告キャンペーン（小・中・大）：一時的に駅の評価を上げる
  - 道路の再整備：道路が半年ほど使えなくなる（ライバル妨害にも使える）
  - 社長の銅像：駅の評価がずっと上がる
  - 新しい建物への出資：一時的に町の成長が速くなる
  - 独占輸送権：12か月、ライバルの駅を使えなくする
  - 賄賂：評価を上げるが、ばれると大きな罰
- **自治体の評価**が低すぎると、その町の近くに駅を建てる許可が下りない

### 2.7 お金・財務

`economy.cpp` より：

- 借入：上限まで一定の単位で借りられる。**金利**は難易度設定から始まり、インフレと連動
- 年間の利息 = 借入額 × 金利（マイナス残高にも利息がかかる）
- **破産**：「所持金 − 借入」が借入上限分のマイナスを下回った状態が続くと
  - 4か月目：警告
  - 7か月目：会社が売りに出される（他社が買収できる）
  - その後も回復しなければ倒産
- ライバル会社（AI）と競争。株を買って買収することもできる

### 2.8 信号（`lang/english.txt` `STR_BUILD_SIGNAL_*`）

| 信号 | 内容 |
|---|---|
| 閉塞信号 | 1区間に1列車だけ。基本 |
| 入口／出口／コンボ信号（プレシグナル） | 駅の手前で空いているホームへ振り分ける古い方式 |
| **経路信号**（パスシグナル） | 進路を予約できれば同じ区間に複数の列車が入れる。今の主流 |
| 一方通行の経路信号 | 逆向きからは通れない経路信号 |

### 3.2 OpenTTD と意図的に変える部分

本作の「どこへ運ぶかを選ぶ」物流（企画書 4.5）と、OpenTTD の仕組みは次の点で違う。

| 項目 | OpenTTD | 本作 |
|---|---|---|
| 届け先の工場 | 駅の範囲内で**一番近い工場に自動** | 範囲内に複数あれば**指令で届け先を選べる**（初期値は一番近い所＝OpenTTDと同じ） |
| 貨物の値段 | 貨物ごとに固定（インフレのみ） | **届け先の在庫・需要で変わる**（相場） |
| 工場の在庫 | 上限なし・すぐ製品に変わる | 入力・出力に在庫と上限があり、詰まると生産停止 |
| 2つ材料が要る工場 | ない（材料ごとに別々に製品化） | **両方そろわないとフル生産しない** |
| 製品と町 | 届けても成長に直結しにくい（雪国・砂漠を除く） | 製品の種類ごとに**町の育ち方が変わる** |
| 土地・不動産 | 土地購入はあるが、開発・地価はない | 地価・自社開発が柱 |

→ 「OpenTTD と同じ操作で、OpenTTD より深い物流と街づくりができる」という形を目指す。

### 3.3 参考にする計算式（叩き台）

- **運賃の時間係数**：OpenTTD の「一定日数までは満額 → 段階的に減る」方式を採用（企画書の速度係数をこれに置き換える）
- **距離**：駅間のマンハッタン距離で計算（分かりやすく、プレイヤーが暗算しやすい）
- **駅の評価**：「来る頻度・待っている量・車両の速さ・新しさ」で評価し、低いと貨物が減る方式を採用
- **産業の成長**：輸送率60%／80%を境に増減しやすくなる方式を採用し、本作では在庫・需要の要素を足す
- **町の成長**：「使われている駅の数」で成長速度が上がる方式をベースに、企画書の発展ポテンシャル式と組み合わせる
